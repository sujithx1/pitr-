Docker Compose + postgres/ configs for PITR

Use this template to run PostgreSQL 18 with pgBackRest archiving. Secrets are never shown here — only ${ENV_VARS} placeholders you define locally.

⚠
No secrets in the UI. Passwords, access keys, and real credentials are not displayed. Put them in a local .env file (never commit it) and reference them as ${POSTGRES_PASSWORD}, etc.

docker-compose.yml

Example structure matching the Hostinger / production stack. Copy it, then set variables in .env.

docker-compose.yml secrets → .env only 
version: "3.9"

services:
  db:
    build: ./postgres
    image: postgres:18
    container_name: postgres_db_18
    restart: always
    shm_size: 8g
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
      TZ: Asia/Kolkata
      PGDATA: /var/lib/postgresql/18/docker
    ports:
      - "${PG_PORT:-5432}:5432"
    volumes:
      - ${PGDATA_HOST_PATH:-./postgres_data}:/var/lib/postgresql/18/docker
      - ./postgres/postgresql.conf:/etc/postgresql/postgresql.conf
      - ./postgres/pg_hba.conf:/etc/postgresql/pg_hba.conf
      - ./postgres/pgbackrest.conf:/etc/pgbackrest/pgbackrest.conf
      - ./backups:/backups
    command:
      [
        "postgres",
        "-c",
        "config_file=/etc/postgresql/postgresql.conf",
        "-c",
        "hba_file=/etc/postgresql/pg_hba.conf"
      ]
build / image

Custom Postgres image

./postgres Dockerfile installs pgBackRest on top of postgres:18 so archive-push works inside the container.

environment

Credentials from .env

POSTGRES_USER, POSTGRES_PASSWORD, and POSTGRES_DB are injected at runtime. Never hardcode passwords in the compose file.

shm_size: 8g

Shared memory

Postgres uses shared memory heavily. Raising shm_size avoids shared-memory errors on larger workloads.

volumes

Data, configs, backups

PGDATA persists on the host. Config files mount read/write from postgres/. ./backups is the local pgBackRest repo.

command

Custom config paths

Forces Postgres to load your mounted postgresql.conf and pg_hba.conf instead of image defaults.

ports

Host mapping

${PG_PORT:-5432} maps host → container 5432. Change the host port without editing the image.

.env template (no real secrets)

Create production_ready/.env from this shape. Fill values locally — do not paste production passwords into the UI or git.

.env.exampleplaceholders only
# Database (fill locally — never commit real passwords)
POSTGRES_USER=your_db_user
POSTGRES_PASSWORD=your_strong_password
POSTGRES_DB=your_database
PG_PORT=5432
PGDATA_HOST_PATH=./postgres_data

# Dashboard / scripts
PG_CONTAINER_NAME=postgres_db_18
PG_USER=your_db_user
PG_DB=your_database
STANZA_NAME=db
LOGICAL_PORT=7100
Variable Purpose Shown in UI?
POSTGRES_PASSWORD Database password for the superuser No — placeholder only
POSTGRES_USER / POSTGRES_DB Bootstrap role and database name Names as placeholders only
PGDATA_HOST_PATH Host directory for PGDATA bind mount Generic path, not a secret
S3_* / webhooks Optional cloud / alert credentials Never rendered in this page
